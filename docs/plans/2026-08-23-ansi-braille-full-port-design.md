# ANSI Braille Full Port — Design

**Date:** 2026-08-23  
**Status:** Approved  
**Approach:** A — Full irc.graphics port (14×31 bitmap matching, 9 BlockKinds, smoothing)  
**Context:** IRC Fiber `img2irc` currently uses 14 glyphs with `ct/cb` half-block cost + Viterbi for half, fixed thr 127 braille (now adaptive+dither+Viterbi). `irc.graphics` (waveplate/img2irc) uses 1588 glyphs as `14×31` bitmaps, 9 `BlockKind`s, `render_blocks` per-pixel cost + smoothing, `grayscaleTolerance 16`, `colourSpace` options. Goal: ANSI images look good within `IRC_HARD_LIMIT=512`.

## 1. Architecture

- **Rust:** Copy `GLYPH_BITMAPS` (`char→[[u8;14];31]`) from `waveplate/img2irc` `src/chars.rs` (generated by `mkrust.py`) into `frontend/wasm-img2irc/src/chars.rs` (or keep as `frontend/src/lib/chars.ts` for JS fallback). Port `draw.rs:render_blocks` / `render_braille` / `emit_colourized` / `luma` / `COLOR_CACHE` / `nearest_*` into `frontend/wasm-img2irc/src/lib.rs` (existing wasm, already has `palette.rs` IRC99/ANSI256). Keep `frontend/src/lib/img2irc.ts` as preview fallback using `glyphsToTable` when wasm not ready (`hasWasmSync()` gate).
- **TS:** Add `BlockKind` enum (`full/half/quarter/eighth/triangle/corner/geometric/box/legacy`) matching `waveplate/src/args.rs` ranges. Extend `Img2IrcDialog.svelte` glyph UI: `braille` checkbox exclusive vs `blocks` multi-select (default `default 67`, presets `smooth`/`all` as in `irc.graphics` `glyph-catalog.js`), `glyphs.json` already 1588 groups. Keep `smartGlyphAlphabet` + `smartCompress` for 512B.
- **Build:** `cargo build --target wasm32-unknown-unknown` → `pkg/img2irc_rs.*` via `wasm-pack`, `vite` loads `pkg/img2irc_rs.js` as `render-worker.js` does. `lake build` not needed (Lean already done). Fallback JS uses `GLYPHS` 14 if wasm missing.

## 2. Components & Glyphs

- **Chars:** `GLYPH_BITMAPS` 1588 entries, `gh=31`, `gw=14`, `bp=gh*gw`. Ranges per spec:
  - `full: 0x20,0x2588`
  - `half: 0x2580,0x2584,0x258C,0x2590`
  - `quarter: 0x2596-0x259F`
  - `eighth: 0x2581-0x2587,0x2589-0x258F,0x2594-0x2595`
  - `triangle: 0x25B2,0x25B6,0x25BC,0x25C0`
  - `corner: 0x25E2-0x25E5`
  - `geometric: 0x25A0-0x25FF`
  - `box: 0x2500-0x257F`
  - `legacy: 0x1FB00-0x1FBFF`
- **Allowed:** `GLYPH_BITMAPS.iter().enumerate().filter(cp in ranges).map(i)` → `allowed: Vec<usize>`, fallback `0..len` if empty (as `draw.rs`).
- **Smoothing:** `smooth` (bool), `smoothCandidates: u32`, `smoothOrders`, `smoothShapes`, `smoothNeighbors`, `protectNeighbors` — candidate expansion + neighbour-aware refine (port `smooth` section from `draw.rs` if present, else simple neighbour protect: don't pick glyph that breaks adjacent block's edge).
- **Braille:** Already improved (adaptive `thr`, Floyd-Steinberg `err`, dominant `FG` + Viterbi row palette for `is24`/`is16`/`irc`/`ansi`). Keep.

## 3. Data Flow

```
Image (File) → PhotonImage (photon_rs, w×h) → block_bitmap (pad to gh×gw, AnsiPixel per px)
  → render_blocks(image: &AnsiImage, args: &Args, render: Render) -> String
    for each block_row in image.block:
      for each blk in block_row:
        for gi in allowed, inv in [false,true]:
          split pixels_under_glyph_ones/zeros via bmp[gh][gw]
          avg_color ones/zeros (or invert)
          cost = Σ (orig - avg)^2 (both invert cases)
          best = min cost (break if 0)
        final_glyph = GLYPH_BITMAPS[best].0
        final_fg/bg = avg colors of best
        emit_colourized(&mut out, render, fg, bg, glyph, &mut first/last_fg/last_bg)
      out.push_str("\x1b[0m\n" or "\x0f\n")
    trim_end
  → Viterbi row palette (braille/half) + smartCompress (prune→bisect 0..6→width-4→palette)
  → IRC_SAFE_PAYLOAD=400 / IRC_HARD_LIMIT=512 check, fallback [' ','▀'] at 10 cols
```

- **Palette:** `getMidgardPalette` → `IRC99`/`ANSI256`/`XTERM256`/`smartPaletteA/B`, `is_near_grayscale` `tolerance 16`, `COLOR_CACHE` 8192, `pick_colour` respects `nograyscale`.
- **Dither:** Keep `dither` 0-8, apply before `block_bitmap` as in `draw.rs`.

## 4. Error Handling

- `GLYPH_BITMAPS empty` → return `"Error: GLYPH_BITMAPS empty"`.
- `allowed empty` → fallback all glyphs, log warning if `args.blocks` non-empty.
- `block_bitmap` pad with `AnsiPixel::new(&0)` (black) for non-divisible sizes.
- `alphaMode transparent` → skip `aa < threshold` for luma and colour.
- `render` `Ansi24` panics if `Colour::Index` used — guard with `is24` check before `render_blocks`.
- `w*h` zero → return empty string.

## 5. Testing

- **Unit:** `vitest --project=lib` — existing `img2irc.test.ts`, `aristotleGlyphs.test.ts`, new `braille_compression.test.ts` (already 1 passed), plus `render_blocks` vs `render_braille` golden for `w=20,h=8` rainbow (len check, dominant colour).
- **Visual:** Render same image at `w=80` with `irc.graphics` (via `https://irc.graphics` `renderCurrent` options) and ours, side-by-side `diff` — expect `ΔE < 5` per block for `half`/`braille`.
- **512B:** `estimateLineLengths` `longest <=512` after `smartCompress` for `w=120` photo (already `400→183` for braille truecolor).
- **WASM fallback:** `hasWasmSync()==false` path still renders via JS `glyphsToTable`.

## 6. Trade-offs

- **A (chosen):** Highest quality, matches `irc.graphics`, ~30% slower (14×31 per glyph × allowed ~200 → ~86k ops per block, but `allowed` filtering + `gh*gw` small keeps `<1200` cells Viterbi), needs `cargo` + `wasm-pack` rebuild. **B** (incremental) faster but only 70% gain. **C** (hybrid) most complex, no extra quality over A.

## 7. Rollout

- Phase 1: Copy `chars.rs`, port `render_blocks` to wasm, keep TS fallback.
- Phase 2: Wire `BlockKind` UI, `glyphs.json` groups, `smoothing` controls.
- Phase 3: Visual regression + 512B perf.
